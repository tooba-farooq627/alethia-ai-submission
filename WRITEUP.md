# Engineering Write-Up: Video Indexing Pipeline

## 1. Timings and the Biggest Improvement
Total recorded active session time reached 17h 48m (64,098s) across Colab and Kaggle sessions (including downloads and checkpointing), while total elapsed resumable-run time reached 30h 54m (111,225s) across cloud interruptions. A full FP32 dataset run was not completed, so an initial full-run baseline duration is unavailable. On GPU benchmark runs, batching alone reduced processing time from 722.75s to 688.93s, but enabling FP16 half-precision yielded the largest measured gain, cutting FP32 batch-8 time from 688.93s down to 300.16s. *(80 words / 100 max)*

## 2. The Pipeline
Our pipeline processes all Parquet files present in the specified input directory row by row. PyArrow streams each row's MP4 video bytes to a temporary disk file to avoid decoding large video volumes into RAM. PyAV decodes frames into BGR arrays, extracts presentation timestamps (`PTS * time_base`) relative to the first frame origin, and applies display rotation metadata from `ffprobe`. Frames are grouped into batches and passed to official YOLO11l weights (`imgsz=640`, `conf=0.4`, class-aware NMS `iou=0.7`). Standard model post-processing evaluates all classes up to `max_det=300`, after which the pipeline filters for the five target classes. If CUDA encounters an Out-of-Memory exception, `pipeline.py` recursively splits the failing batch into smaller sub-batches and retries inference in exact frame order. Finally, `SecondAggregator` applies 50% presence voting and floored median people counts for each 1.0s window, writing uncompressed JSONL output records. *(147 words / 150 max)*

## 3. The Bottleneck and Its Measurement
System profiling established that throughput was dominated by neural network model inference rather than video decoding or file I/O. On a 3-video profile sample (29,782 frames, 1,082 emitted seconds) run on a T4 GPU, coarse stage wall timing showed total file processing required 279.48 seconds. Within this total, model inference and per-frame count processing consumed 251.50 seconds (roughly 90% of file-processing wall time), whereas PyAV video decoding required 27.31 seconds (approximately 10%), with aggregation and I/O consuming negligible time. These coarse stage measurements confirmed that inference execution represented the primary system bottleneck during this benchmark sample. Consequently, performance optimization efforts focused on GPU inference parameters—specifically batching and FP16 half-precision execution—to reduce the dominant stage of overall wall-clock processing time. *(130 words / 150 max)*

## 4. Correctness Checks
We evaluated FP16 CUDA batching against FP32 reference outputs across 12 complete dataset videos (3,692 output seconds). On this validation subset, FP16 achieved an object micro-F1 of 0.99965 (above the required 0.95), exact people count agreement of 99.95% (above 85%), and within-one agreement of 100.0% (above 95%). These metrics verify close agreement with the reference model on the test set, though performance on the unseen grader set remains unmeasured. Additionally, 33 automated unit, integration, and regression tests—utilizing synthetic failure fixtures for memory retries, rotation, irregular timestamps, and checkpoint recovery—verified code correctness. *(97 words / 100 max)*

## 5. One Wrong or Rejected AI Suggestion
During cloud monitoring setup, an initial AI implementation set `last_snapshot = 0` in `watch_run.py` and checked `time.monotonic()` to trigger backups every 10 minutes. On a freshly booted machine, `time.monotonic()` was under 600 seconds, so the interval check failed, skipping initial snapshot creation. The script then attempted to check the size of the non-existent archive file, crashing with a `FileNotFoundError`. Recognizing the logic flaw, the AI revised the implementation to use an explicit `None` state ("no snapshot yet"), forcing an immediate initial backup on boot, and added a regression test simulating low boot clock values to verify the fix. *(99 words / 100 max)*

## 6. Next Steps with Another Week
Given an additional week, we would explore several performance and architectural enhancements. First, we would evaluate exporting YOLO11l to TensorRT or ONNX Runtime with FP16 or INT8 quantization to reduce framework and execution overhead on NVIDIA hardware. Second, we would implement an asynchronous queue architecture to overlap CPU video decoding with GPU model inference, eliminating GPU idle time between batches while expanding on PyAV's current multi-threaded decoding. Third, we would develop dynamic batch-size auto-tuning based on runtime VRAM availability to optimize GPU memory utilization and throughput when running on higher-capacity GPUs like an RTX 4090. *(97 words / 100 max)*
